## 20:00–20:30 — Bug audit of the booking implementation (report: `BOOKING_BUG_REPORT.md`)
Findings, highest first:
1. **HIGH** `BOOKING_STORE=memory` is broken: both API routes call `ensureBookingSchema()`
   unconditionally, which rejects when `DATABASE_URL` is unset → 503 even though
   `repository.server.ts` supports the memory store. Reproduced.
2. **HIGH** rate limit 6/min/IP on POST counts 409/400 retries; mobile CGNAT IPs can
   lock out real customers.
3. **MED** `ScheduleStep` empty/failed-availability branches have no BACK button → dead end.
4. **MED** `DayStrip` inline ref callback re-runs `scrollIntoView` on *every* render.
5. **MED** `referrer`/`landing_page` attribution never persisted (client never sends
   `referrerHost`; server always gets null).
6. **MED** service type silently defaults to `kitchen` → "Choose a project type" unreachable.
7. **MED** horizon off-by-one: API accepts today+30, UI offers only today+29.
8. **MED** `scroll-snap-type` on `.bk-days` instead of `.bk-days-scroll` → snapping is a no-op.
9. **MED** idempotency `requestId` returns full PII with no ownership proof.
10. **LOW** `BOOKING_SETUP.md` missing the required "Google Calendar Integration — TODO" and
    "Meta Ads Integration — TODO" sections (ends at §6).
Also: leftover `full_name='Testing'` row at 2026-09-22T17:00Z still blocks a slot.
